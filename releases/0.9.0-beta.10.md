# Viandly 0.9.0-beta.10

Released: July 24, 2026

This closed-beta update makes scanner-assisted importing faster to operate in bulk while
preserving clear human review, recoverable source evidence, and fair background execution across
accounts.

## Highlights

- Added opt-in automatic scanner processing. New scanner deliveries can proceed directly to the
  account's verified vision-capable AI provider without opening each delivery first.
- Kept manual review as the default. Viandly records the processing choice when each delivery is
  accepted, and existing accounts do not begin sending scans to AI without explicit consent.
- Preserved recoverability when automatic processing cannot start. Provider, entitlement, import
  capacity, or service changes leave the original delivery ready for manual review.
- Expanded the bounded per-account waiting queue while retaining one active expensive job per
  account. Users can submit several scans in succession without monopolizing shared workers.
- Distinguished **Enqueued** work from **In progress** work throughout the Inbox. Opening or
  editing a draft no longer makes it look like background processing is still running.
- Added an owner-checked original-scan viewer inside Viandly, including responsive source review,
  source switching, zoom restoration, installed-app navigation, and optional separate-window use.
- Added a direct **Discard draft** action when duplicate detection identifies an import the user no
  longer needs. Discard remains reversible through Trash.
- Updated scanner and AI help with automatic-processing consent, provider billing, queue behavior,
  source retention, and recovery guidance.

## Tester Guidance

Under **Account Settings - Scanner Imports**, choose **Automatically analyze with AI**. The option
requires an AI provider whose selected model has passed the image-input test. Send several scans in
succession and leave the Inbox open. Waiting work should show **Enqueued**, only the worker's
current item should show **In progress**, and completed work should become individual draft or
source-review rows.

Open a generated draft and compare it with **Original scan**. On a larger screen, confirm that the
source can remain beside the recipe; on a phone or installed app, confirm that the source workspace
has an explicit return path. When a possible duplicate appears, confirm that **Discard draft**
moves only that draft to recoverable Trash.

Switch Scanner Imports back to **Review each delivery** before sending another scan. That new
delivery should remain ready in the Inbox until a processing method is selected.

## Release Identity

The product version is `0.9.0-beta.10`, with source tag `v0.9.0-beta.10`. The About and Help
interfaces show the corresponding 12-character source revision.

## Compatibility

This release adds a data-preserving scanner-processing preference that defaults to manual review.
Existing scanner deliveries, source captures, import drafts, recipes, provider connections, and
queued work remain supported. The REST API version is unchanged.
